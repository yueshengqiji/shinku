# QQ 聊天层

聊天层不是“短回复模板”和“长回复模板”的切换器，而是给模型提供一个很小的
语境提示，并记录话题是否仍在延续。

## 工作方式

1. 新话题或首次被叫到：提示模型先给最小充分答复。
2. 同一发言人继续同一话题：提示模型判断有没有新的未解决点，有才展开。
3. 上一轮已经展开：下一轮进入短暂冷却，避免回复长度逐轮累加。
4. 话题切换或超过 TTL：状态重置。

模型仍然决定具体内容、语气和是否真的展开；聊天层不会生成固定台词，也不会
直接删除模型输出中的“嗯”或“我在这里”。只有同类陪伴性开场在最近几轮重复时，
才会在下一轮提示模型自然换一种开头。真正需要安慰、停顿或确认陪伴时，这些表达
仍然可以使用。

现有 `ReplyHost` 的长度阈值、句号断句和最终气泡上限保持不变。聊天层状态只存在
于运行内存，不写入长期记忆，也不进入固定系统提示词；固定的聊天原则位于系统
提示词，动态的小提示位于用户提示词末尾，以保持缓存前缀稳定。

## 配置

```text
SHINKU_QQ_CHAT_FLOW_ENABLED=true
SHINKU_QQ_CHAT_FLOW_TTL_SECONDS=600
SHINKU_QQ_CHAT_FLOW_COOLDOWN_TURNS=1
SHINKU_QQ_CHAT_FLOW_VOICE_WINDOW=4
```

群聊按“群组 + 发言人”隔离状态，避免一个人的连续追问让整个群进入长回复节奏。
