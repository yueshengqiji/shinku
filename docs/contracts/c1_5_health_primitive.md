# C1-5 契约：进程健康载荷原语

**本批类型：契约事实迁移。** 判定依据（来源记录 §5.9 路径 A，判据表见 `SOURCE_RECORD.md` §4.2）：

| 项 | 事实 |
| --- | --- |
| 有无分支 | 无 |
| 有无算法／数据处理 | 无 |
| 有无状态 | 无 |
| 文件形态 | 1 个模块 docstring + 1 个函数 + 1 条 `return` 字典字面量 + `__all__` |

零分支、零算法 ⇒ 归「纯契约」类：**函数名、无参签名、返回类型、四个字段名与各自的取值语义属接口信息，允许按事实迁移**；
docstring、注释、内部组织与文件定位由 Shinku 撰写。**本批不制造人为差异**——
为凑一个「与上游不相似」而把字典字面量改写成别的结构，只会牺牲可读性，
并不降低法律风险（`SOURCE_RECORD.md` §5.6）。

## 1. 契约事实（迁移项，逐条可核对）

| # | 契约事实 | 取值 |
| --- | --- | --- |
| 1 | 模块导出面 | `__all__ = ["build_basic_health_payload"]`（唯一名） |
| 2 | 函数名 | `build_basic_health_payload` |
| 3 | 签名 | 无参数，不接受任何位置参数或关键字参数 |
| 4 | 返回类型标注 | `dict[str, Any]` |
| 5 | 返回键集合 | `status` / `pid` / `python` / `yt_dlp`——**恰为这四个**，多一个少一个都是迁移错误 |
| 6 | 键顺序 | 构造顺序即上表顺序（`dict` 保序；这是实现内可观察量，不作为线路契约） |
| 7 | `status` | 字面量 `"ok"` |
| 8 | `pid` | `os.getpid()`——**本进程**号，不是父进程 |
| 9 | `python` | `sys.executable`——当前解释器可执行文件路径 |
| 10 | `yt_dlp` | `bool`：`importlib.util.find_spec("yt_dlp") is not None`，即「装没装」，**不是「能不能导入成功」** |

## 2. 外部可观察行为（不只迁移，还必须是这个行为）

1. **每次调用返回新字典。** 不返回模块级共享实例——调用方会把返回值展开进更大的载荷，
   共享字典被就地改写后，其余调用方拿到的就不再是进程事实。
2. **探测不导入。** `find_spec` 只查元数据，不执行 `import yt_dlp`；
   调用后 `sys.modules` 里不应出现 `yt_dlp`。这条是契约而非实现细节：
   探针路径必须即时，导入一个大依赖会把响应拖到超时。
3. **探测失败不抛异常。** 依赖不存在时 `find_spec` 返回 `None` ⇒ `yt_dlp` 为 `False`，
   而不是抛 `ModuleNotFoundError`。
4. **调用无副作用。** 不读环境变量、不读配置、不写文件、不碰网络。
5. **是活的。** 在另一个进程里调用得到的是**那个**进程的 `pid`，不是调用方的。
   这一点把本原语与「返回写死字典」区分开——见测试 `test_the_payload_describes_the_process_that_built_it`。

## 3. 明确不迁移的东西

| 不迁移项 | 理由 |
| --- | --- |
| 旧模块的两个英文 docstring | 表达层，Shinku 自撰 |
| 旧模块在外置包里的导出位置（包级 `__init__` 再导出） | 那是旧侧「外置包 + 兼容壳」架构的产物；Shinku 是单仓，包级再导出由本仓的包导出面自行决定 |
| 旧侧的「两份同内容文件」布局 | 见 §4.3 |

## 4. 事实来源与表达层（分列登记，禁止用一句话概括）

### 4.1 事实来源

`build_basic_health_payload` 的**函数体**（`return` 语句的字面量、键名、键序、四个取值表达式）
与上游实现逐字相同，属 §1 表内的契约事实迁移。

### 4.2 表达层：Shinku 撰写

- 模块 docstring（旧侧是 `Framework-neutral process health payload primitives.` /
  `Process-level health facts for the Shinku backend.`，均未沿用）；
- 函数 docstring（旧侧函数 docstring 为 `Return the process facts common to both local companion backends.`，
  未沿用）；
- 函数体内的两条注释（新写入，说明「新造字典」与「只探测不导入」两条契约的理由）；
- `from __future__ import annotations`、导入语句的书写方式与空行组织。

**表达层的独立性与契约事实的迁移是两件事，必须分开读。** 本批相似度高是预期结果，不是缺陷；
判据看本节是否有分列，以及 §5 的检查读数。

### 4.3 文件定位：为什么是单文件而不是包

旧侧存在**两份内容相同的 `health.py`**（外置共享包一份 + 项目树内一份），
这是旧侧「外置包 + 项目内兼容副本」架构的产物，不是设计意图。Shinku 是单仓，
本原语按顶层模块落位（与 `names.py` 同级），不给它单独建子包——
顶层模块这一层在本仓的口径是「跨服务的进程级原语」，`health.py` 落在这里由定位决定，
不是由上游的文件名决定。

## 5. 已知瑕疵登记（**登记，不顺手改**）

契约原样迁移意味着上游的设计瑕疵也跟着进来。把它们写下来而不是私下改掉——
一个被登记的瑕疵是信息，一处未被解释的微小改写是噪声。

| 瑕疵 | 现状 | 为什么本批不改 |
| --- | --- | --- |
| `yt_dlp` 是硬编码的单点依赖名 | 一个声称「进程级」的原语里钉着一个具体产品名 | 改成参数或探针表都会改动**签名**，那是契约事实，不属于本批权限 |
| 新仓库当前**没有** `yt_dlp` 依赖 | 该字段在 C4 接入附件下载链路之前**恒为 `False`** | 本批不引入新依赖（依赖只加「当前模块真正用到的那一个」）；这条留给 C4 决定「接入依赖」还是「这个字段在本项目里已无意义」 |
| 旧侧 `/health` 直接返回这四个字段作为整个响应体 | 上游同位置是 `{**build_basic_health_payload(), "contracts": {...}}`，多一个 `contracts.desktop_pet` 块 | 那是**消费者**的差异，不是本模块的差异；本批只迁移模块。已作为差异定位记入批次记录，意图未经验证，不作断言 |
