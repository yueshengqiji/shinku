# C3-2：任务快照与事件边界

## 本批交付

`shinku.tasks.workspace` 提供一个只依赖注入存储的 `TaskWorkspaceService`：

- 创建任务快照并写入 `task_created` 事件；
- 按身份、会话、状态读取任务；
- 更新任务状态、目标、步骤、产物、待确认问题和元数据；
- 追加事件、读取事件、标记事件已处理；
- 完成与清理任务时自动写入生命周期事件。

输入先经过 C3-1 的状态和 payload 归一化，存储层仍负责真正的状态迁移、事务和持久化。

## 明确不做

本批不实现 SQLite/文件存储，不调用模型或工具，不渲染提示词，不接 QQ/HTTP，也不负责后台线程。下一批再把执行器的输入、工具调用结果和工作区事件接起来。

## 存储协议

存储对象只需实现 `WorkspaceStore` 中声明的方法，并返回 JSON 形状的字典。这样测试可以用内存假件，生产环境可以接独立数据库而不改变 Agent 服务的领域接口。
