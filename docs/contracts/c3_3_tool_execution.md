# C3-3：工具调用、结果封装与失败边界

## 本批交付

`shinku.tools.execution` 将一次工具轮次拆成四个可测试阶段：

1. 用 `ExecutionPolicy` 检查本轮允许/禁止的工具；
2. 用注入的 handler 做工具名和参数校验；
3. 调用一次 handler，并保留原始结果给上层；
4. 将成功、空结果、校验失败和 handler 异常统一封装为 `ToolResultEnvelope`。

## 设计边界

- 不决定模型是否应该调用工具；
- 不执行多轮 Agent 循环；
- 不做 QQ 媒体特判、截图特判或后台委派；
- handler 异常不会把内部异常文本直接送回模型，只回传稳定错误码和异常类型；
- 状态更新和流式事件保留在 envelope 中，具体落库由 C3-2 工作区服务或更上层处理。

后续 C3-4 再将这个单轮执行面接入“计划 → 工具 → 结果 → 重新规划”的循环，并处理最大轮数、重复调用和恢复策略。
