# C4-1：入站消息与附件边界

## 目的

QQ、HTTP 或其他消息适配器的原始事件不能在入口处把图片、文件、音频和引用压成
`[图片]` 等纯文本。那样模型既无法知道是否真的有附件，也无法在后续工具轮次里
找到原始引用。

## 契约

`IncomingMessage.from_event()` 把事件归一化为：

- 顶层消息 ID、发送者、会话和会话类型；
- 有序的 `MessageSegment` 列表；
- 文本视图 `text`，只拼接文本/@/表情片段；
- 独立的 `attachments` 视图，保留媒体类型、媒体 ID、URL 和本地路径；
- `raw_event`，保留适配器尚未声明的字段，供后续能力层取用。

图片和文件不进入 `text`，但也不会被丢弃。引用 segment 同样保留原始 payload；
是否读取附件、是否回复引用和如何投递，留给后续 C4 路由与能力策略决定。

## 灰度口径

本批只测试纯 Python 事件归一化，不连接 QQ、NapCat、数据库或图片下载器。它证明
的是入口信息不丢失，尚不代表真实 QQ 事件适配已经完成。
