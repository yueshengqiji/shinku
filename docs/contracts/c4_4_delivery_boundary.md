# C4-4：出站消息与附件投递边界

## 目的

回复文本、图片和引用必须作为同一轮出站请求交给 QQ 适配器。入口或 Agent 层不能
先发文字、再猜测图片状态，也不能在附件投递失败时额外生成“看不到图片”之类的
替代回复。

## 契约

- `OutgoingMessage` 至少包含一段文本或媒体；
- 文本、图片、文件、音频、视频和引用 ID 保持在同一个请求对象中；
- `DeliveryTransport.send()` 只负责外部投递，具体 QQ/NapCat 协议留在适配器；
- `deliver()` 只返回 `DeliveryResult`，成功、拒绝、传输异常和无效 transport 分开；
- 失败不生成 fallback 文本，也不把未确认的消息标成已发送。

## 灰度口径

本批使用记录式 transport，验证一条请求内同时携带文字、图片和引用，以及失败状态
不会被伪装成成功。没有连接 QQ、NapCat、图片下载器或网络。
