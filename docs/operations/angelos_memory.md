# Angelos 独立记忆

实施与验收状态见 独立记忆计划（历史/本机资料，未随此快照提供）。

## 数据所有者和调用顺序

```text
Workbench 原始输入 / 工作区快照
  -> 原 AgentService / AgentTaskStore（唯一执行状态与回执）
  -> TaskContinuity + task_memory（当前任务与历史候选，只读派生）
  -> build_execution_prompt（根输入保存当前视图，稳定控制块保存历史关联）
  -> 原 AgentLoop / 工具 / CompletionVerifier
  -> canonical result
  -> Workbench.capture_memory -> AgentMemoryStore（可重试的经验副索引）
```

`ServiceHost(..., memory_root=专属目录, memory_policy=AgentMemoryPolicy(...))` 显式接入。
未接入时不创建库、不注册记忆工具；不从环境猜测 Bot 路径。独立工厂准备的目录为
`<Angelos 数据目录>/memory/agent-memory.sqlite3`，由启动进程首次创建，源码修改不等于正式加载。

- `AgentTaskStore`：原始要求、尝试、预算、实际工具回执、验收与结果 seal。
- `WorkbenchStore`：用户输入、会话归属、工作区快照及结果展示副本；副本不能覆盖执行事实。
- `AgentMemoryStore`：Agent 独立用户陈述和经验索引、本库 FTS、同源撤销墓碑。
- `TaskContinuity`：同会话明确 task ID 或最近任务候选；不恢复任务、不继承权限。
- 原 `work_state`：可选对象候选和冲突、步骤、假设及来源引用；都是模型导航，不是确认事实。

当前效果、整体目标、报告交付分别展示。失败任务可能已有安装/文件效果；成功工具也可能没完成用户目标。
记忆视图展示的是“账本曾记录什么”，不能证明软件现在运行，更不能因同名而合并不同产品。

## 三重隔离

1. **存储**：专属目录、专用 SQLite application_id/身份表、仅本库 FTS。拒绝 Bot 目录、外来库、软链接、硬链接和不合格权限，不修改外来库来适应。
2. **检索**：`agent_memory/retrieval.py` 独立词项与排序入口；不实例化 Bot 的 MemoryService/MemoryRouter，不共享记忆查询缓存。当前任务按 ID 读取，不走相似度召回。
3. **配置**：`AgentMemoryPolicy` 是每个实例的不可变配置，不读取 Bot 的强化/晋级/生命周期配置，不把曝光或召回算成强化。

库内部按宿主 requester 与工作区 id/path/description 的绑定隔离。浏览器、模型工具参数不能选择 requester、工作区、SQL 或路径。
修改工作区绑定后旧来源不自动搬迁。跨 Agent 会话可以在同一绑定中回查；跨 Bot 不支持导入、查询或自动同步。

## 本批检索的实际能力

独立 SQLite FTS5，英文标识符分词和中文二元字串，版本号拆分匹配；不推断别名、不建立通用实体图、没有向量调用。
默认候选 32、交付 4、查询 512 字符、展示最近 6 轮，库记录上限 4096。配置边界在 policy 构造时校验。
结果注明有界词项检索，命中不代表全面召回；找不到不代表从未发生。

先按 scope 过滤再返回候选，逐条回查原输入或原 canonical result。任务经验依赖原任务保留期，过期/新尝试/版本变化返回来源缺口。
用户陈述回查工作台原文，不依赖短期任务 TTL；源输入被删除、修改或换工作区即失效。读取不刷新原件寿命，不触发任务库清理。

## 管理工具与来源

- `read_agent_memory(query)`：只读本库，签发本次观察凭据；完成时重验查询、scope、源版本和正文哈希。
- `manage_agent_memory(operation=remember, message_id=..., text=...)`：在当前循环声明 `effect=memory_manage, targets=[]`，并满足原工具策略及 full/ultra 模式。
  当前用户须明确请求记住；条件句、转述、否定或引用前缀不据关键词触发。超出窄准入语法时明确拒绝，不增加固定模型核对。
  片段只能定位当前用户原输入，实际保留整条原话，包括条件、否定和归属。含秘密的输入拒绝记忆写入，不把模型猜测保存为偏好。
- `manage_agent_memory(operation=forget, id=...)`：须有当前用户明确忘记请求，按当前身份与工作区删除本库正文/索引，留下无正文墓碑。
  同源用户陈述和经验一并撤销，迟到的自动索引不能复活。后续自动历史投影也停止提供该来源，原会话与任务审计不删除；按用户当前请求回读仍受原权限控制。

`memory_manage` 只证明记忆变化，不能证明文件、命令、安装或消息发送。只有窄且完整的记忆收尾子句和有效本库签名同时满足，才避免被误判成文件保存声明；其余行动继续原严格验收。
原回执压缩只额外保留 handler 显式声明的观察签名字段，不从模型参数制造执行凭据。

## 历史与压缩

原完整历史继续在工作台和任务中保存。聚焦只改变模型输入投影，附 `read_task_records` 的原输入/任务回读导航。
最新两项业务任务从原账本读取，明确 task ID 优先；候选不等于用户已经选择恢复，普通聊天不挤占业务任务候选。
当前用户要求、硬条件和原生 assistant/tool 配对不变，九成摘要仍走原预算和原文留存。
稳定历史关联进入受保护控制块；每次 observe 的版本变化不重复追加整份当前任务视图，以免不可摘要控制块膨胀。

## 失败、并发和回滚

记忆索引在 canonical result 之后执行，与任务库不是同一事务。失败只记录 `memory_error`，不改业务完成状态，不重做工具；同源 key 幂等且尊重遗忘墓碑。
管理写入在原 service 锁内重新核对当前输入、权限与绑定。记忆和 FTS 同一 SQLite 事务写入；检查完成后若撤权，可能已有写入，明确报告不确定而不伪称“无变化”。
数据库身份或路径错误明确失败，不回退 Bot。当前文件边界按 POSIX 权限校验，Windows 行为未验收，不能宣称跨平台上线。
回滚接入代码只停止使用，保留本库、原任务和审计。不回滚已执行的业务操作，不删除 Bot 数据。真实模型质量、自然指代召回与正式部署须另行验收。
