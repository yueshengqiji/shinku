# 聊天侧读取当前实例状态

`read_self_state` 在工具注册表中存在，并不代表 task 聊天模型能够使用它。
聊天模型的原生工具目录还必须包含宿主提供的 `ChatReadCapability`。
缺少这一步时，询问当前聊天模型、工具或配置的请求可能被委托给 Angelos；
Angelos 的同名工具观察的是执行实例自身，不能用来证明 Shinku 的聊天模型。

## 装配与边界

阅读顺序为 `src/shinku/qq/assembly.py` → `assembly_tools.py` →
`interaction_tools.py` → `src/shinku/agent/self_state.py` → `self_state_receipts.py`。

1. QQ 装配创建当前聊天 runtime 的状态 provider，注册内置 `SelfStateTool`。
2. `self_state_read_capabilities` 仅为类型完全匹配、绑定同一个 provider、配置了
   新鲜读取入口的内置工具补充聊天目录。同名插件、子类或其他实例的工具不自动准入。
   显式宿主目录中的条目保持优先，允许宿主提供更窄的范围。
3. 模型必须提供 `scope`，可选 runtime、agent、tools、persona、config、changes、all。
   问当前模型时读取 runtime 即可；整体自查才需要 all。参数不能指定路径、命令或远端目标。
4. 原有主人、启用状态、工具目录和执行策略继续决定是否展示、准入和执行。
   只读适配器最多执行一回合一次、单次 10 秒、结果最多 64000 字节；
   内置工具原有安全投影、裁剪和回执规则保持。
5. 状态归属由本地 provider 决定，runtime 含 `instance=shinku_chat`。
   provider 每次读取实际 runtime 的模型字段；这表示客户端当前配置，不能证明供应商底层权重。
   Angelos 保持自己的状态 provider，没有获得读取聊天宿主的通用入口。
6. 读取凭据由原有宿主观察存储持有，绑定请求者、会话、消息、范围、时间和快照摘要。
   刷新失败、缓存、缺失、裁剪、过期或篡改均不能认证为新鲜完整状态。
   状态快照不认证服务健康、部署完成或消息送达。

该改动没有新增关键词分类器，也没有强制禁止委托。模型看到真实能力后自主选择；
“目录可见”和“隔离协议可执行”不等于真实模型在每次提问中都会正确选用。
