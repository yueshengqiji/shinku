# 控制中枢本机对话

打开 `/debug/hub#conversations`，在“和真红对话”中输入正文，点击发送或按
Ctrl / Command + Enter。模型名称来自当前 Bot 实例的运行状态，而非另一个
Agent 工作台或浏览器自选配置。

页面复用 `/api/pet/chat` 的桌面渠道，沿用 Bot 的人格、会话、权限与记忆链路；
不实例化 Angelos，不连接其独立记忆库，也不触发 QQ 发送接口。实际可用的
工具和外部投递能力仍由该后端实例的装配配置决定。

页面正文仅保存在当前 DOM，刷新后不恢复显示；“新对话”只更换本机对话定位符
并清空页面，不删除后端原文、记忆或审计。状态轮询不重绘聊天正文。

一次只发送一条请求，等待期间禁用发送、新对话与编辑。网络失败保留输入，
展示具体错误，不自动重试，因为未取得响应不代表原请求没有执行。原接口没有
跨网络重试去重保证；重发前应核对控制台的回合记录。

启动使用原后端入口及其配置。保存的激活供应商会优先于环境中的默认模型，
应同时核对实际配置目录、`activeProviderId`、模型目录与运行状态中的模型名。
不同实例可以读取不同注册表，不应只检查工作区任意一份同名配置就判断归属。

离线回归为 `tests/test_debug_hub.py` 与 `tests/test_pet_api.py`，按项目规则经
桌面批处理入口运行。接口测试和模型目录可用不代表真实生成成功，真实模型
回复及其用量需单独核验。启动服务与登录自启分别管理。


## 桌面与 QQ 的记忆承接（源码增量，加载状态见专项计划）

桌面必须能从宿主配置确定唯一主人；没有或配置多个主人时返回身份不明确，
不任意挑选一个身份。客户端的会话 ID 会映射到独立桌面命名空间。
桌面回合参与原会话状态系统，用户原话及实际返回的助手正文进入 Bot 的主人共享记忆。

普通桌面回复在 HTTP 响应体成功交给传输后才生成本地回执。该回执只证明传输，
不证明用户阅读；传输异常不记录已送达助手正文。即使 QQ 发送器已配置，
桌面也不会通过它发送，不会在并发请求中替换全局发送器。

两端连接同一 Bot 记忆库时，提交后的原文会在下一轮构造提示时直接重读，
无需等待向量索引或摘要。自动承接默认最近 300 秒、最多 6 条及 3200 字原文，
单条过长则留给显式检索，保留条件和否定而不截断原文。
`SHINKU_MEMORY_OWNER_CONTINUITY_SECONDS` 可设为 0 关闭，最大 1800 秒。
时间窗只限制自动承接，不删除长期记忆；时间以保存原话的记录为准。

自动共享只进入主人的桌面和 QQ 私聊。群聊仍按既有显式检索与身份规则读取，
不会自动注入私人上下文。生成前后检查来源、版本、时效和权限；
另一端增加新信息、撤销来源或更改身份时，过期候选不能继续发布。
共享记忆中的遗忘同步约束精确同源原件，不按相同文字删除其他人的记录。

本能力不连接 Angelos 的独立记忆库，也不在不同数据库之间创建网络同步服务。
重建实例后可从同库恢复有效期内的承接；旧桌面记录不会无证据地批量补录。
聊天时间不能证明程序的启停或睡眠时长。阶段、测试和部署边界见
专项计划（历史/本机资料，未随此快照提供）。
