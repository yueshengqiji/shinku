# 本机文件、测试产物与证据归档

## 文件归属

| 类别 | 位置与用途 | 保留原则 |
| --- | --- | --- |
| 公共实现与合成测试 | `src/`、已跟踪的 `scripts/`、`tests/` | 随明确源码快照提交，公共检出能独立验证 |
| 本机历史脚本、集成测试与原始报告 | 按 `private/local-workspace/files.json` 登记原路径、摘要及原因 | 既有引用有效；仅通过 `.git/info/exclude` 精确排除，不公开原件 |
| 正常批处理输出 | 启动器输出的磁盘 `TMPDIR` 下 `batch-*` | 每批独立；失败日志与回执保留，不在测试结束时一律删除 |
| 私用评估、维护、迁移材料 | `private/evaluations/`、`private/maintenance/`、`private/migrations/` | 正式结果、首错、冻结输入、回滚材料保留，按批次登记 |
| 运行副本、配置与数据库 | 实际服务启动路径及其数据根 | 必须先核实真实引用；工程清理不负责回滚或删除业务数据 |
| 历史补丁与计划 | `docs/` 原有记录 | 保留原路径；从文档导航进入当前计划 |

被本机排除的文件仍是未入库的本机材料，不是已提交源码。核查时同时读取
`private/local-workspace/files.json` 和 `git status --short --ignored`；新增文件
仍正常出现在 Git 状态里。精确排除规则不能代替公开内容审查。

## 测试输出

Linux 批次统一通过 `scripts/run_desktop_batch.py`。pytest 的 `tmp_path` /
`tmp_path_factory` 跟随批次临时目录；显式 `--basetemp` 也必须放在磁盘缓存中。

联合验收驱动的 `ROOT` 保持源码和语料身份，`OUTPUT_ROOT` 单独限定产物根。
CLI 默认仍是仓库 `tmp/`，不接受环境变量自动扩大真实验收的允许路径。
pytest 夹具只覆盖自己加载的模块实例；共享私用驱动在夹具结束时恢复原值。
工作区与账本必须互不嵌套、尚不存在且位于选定输出根内，原有检查继续执行。

测试输出位置变化不改变真实调用授权、原有预算、输入身份、判据或失败状态。
临时目录由 pytest 和批次管理；需要长期接续的证据显式归档并登记，不能仅靠
“一直没有删”保存重要结果。

## 旧目录归档顺序

1. 记录候选目录、文件摘要、原权限和字节数；区分自动生成的合成测试与正式验收。
2. 排除当前进程打开的文件、工作目录和命令行引用，以及计划、脚本、报告仍引用的材料。
3. 按明确批次建立压缩归档与路径清单；逐文件核对归档内容和原件 SHA256。
4. 再核对活动引用及原件变化，确认一致后才移除已归档的原目录；不使用全树清空命令。
5. 保留首错、正式报告、恢复说明和压缩包摘要；抽取到独立位置验证恢复，禁止覆盖新文件。

归档清单、包和执行记录放在本轮 `private/maintenance/` 目录。目录名、日期、
Git 忽略状态或文件体积本身都不是删除依据。不能核实的目录保留并列出原因。
