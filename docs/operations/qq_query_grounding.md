# QQ 查询要求与直复证据边界

## 故障与范围

当一轮消息带有历史图片候选时，旧流程在模型选择 `visual_context.action=none` 后，直接复用选择阶段的正文。该阶段没有原生工具接口，格式纠正还要求同时给出普通答复，因而可能让明确的查询请求以未执行的普通答复结束。原有行动承诺检查也没有覆盖“翻过资料”等已执行查询自述。

本次修复以 `173ea157e6a655ea733265e269c5fb7152ab4c90` 为源码起点，仅修改 QQ 聊天入口、图片确认后的决策与直复出口。已有只读查询、资料核验、独立执行、权限、任务预算和送达链路继续负责真实执行。运行实例、模型配置、记忆数据库和私用扩展不随源码提交更新。

## 行为规则与阅读顺序

1. `visual_selection.py` 只确认图片来源。`select` 和 `none` 都回到正式决策；`clarify` 仍只返回消歧问题。候选失效、读取失败或预算拒绝保持终止，不靠重试获取另一份来源。
2. `task_interaction.py` 与兼容入口 `chat_decision.py` 恢复本轮工具接口后重新请求决策。选择阶段正文不进入最终送达；任务模式保留原有记忆读取引导与委托能力上下文，仍拒绝夹带的权限字段。
3. `query_grounding.py` 提供本轮查询依据提示和有界的文本兼容检查。明确查询要求只从宿主 `RequestScope` 的当前主消息读取；群聊背景、历史助手正文、模型填写的状态均不是查询回执。检查不选择工具或扩大权限，也不把某个产品名称编码为特殊规则。
4. 普通正文未满足明确查询要求，或声称本轮已经查询时，入口最多使用原有一次纠正机会，让模型选择已有获准接口。纠正后仍无执行则返回未核实状态。失败或澄清可正常返回，但不能夹带已执行查询的自述。
5. `turn_routing.py` 在直复发送前再次检查，防止其他直接答复入口绕过。真实只读查询与委托结果继续走各自的回执核验出口，不用此处的文本检查替代来源验证。

## 限制与代价

- 文本兼容检查覆盖明确的查询句式和当前查询自述，不是完整语义理解，也不能证明任意事实答案准确。主生成仍需遵守不确定性、来源与执行事实边界。
- 有图片候选但无需看图时，比旧流程多一次正式决策；无候选普通闲聊保持一次调用。图片格式最多纠正一次，正式决策最多纠正一次，两者继续受原任务总预算约束。
- 此修复不保证模型已掌握某一产品，不修改记忆检索策略，不写入产品词条。
- 回滚时还原本次源码提交即可；未进行运行加载，无需回滚生产数据。
